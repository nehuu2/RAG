Vector Stores for RAG

ChromaDB

ChromaDB is a vector database that can be used locally for retrieval applications. It stores embeddings together with documents and metadata, making it useful for a compact RAG prototype.

Why metadata matters

Metadata makes retrieved chunks traceable. A useful record can include the source filename, file type, page number, and chunk identifier. Metadata can also be used to restrict retrieval to selected documents or file types.

Idempotent ingestion

Idempotent ingestion means running the ingestion process repeatedly does not create duplicate vectors for the same logical chunk. A deterministic identifier based on source information and chunk position is one practical way to achieve this.

Retrieval pipeline

A query is embedded using the same embedding model family used for document chunks. The vector store returns the nearest candidates. The application can then apply a similarity threshold and construct a grounded context for the generator.

No-context behavior

If no retrieved chunk passes the relevance threshold, the application should not fabricate an answer from unsupported information. It should report that the supplied corpus does not contain enough relevant context.
